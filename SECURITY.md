# Security Policy

## Supported versions
During early development, only the latest default branch is supported.

## Reporting a vulnerability
Do not open a public issue for an exploitable vulnerability. Use GitHub's private vulnerability reporting feature when enabled, or contact the organization security contact listed in its profile.

Include affected version/commit, impact, reproduction steps, and a proposed mitigation if available. Do not include real victim data or live malware URLs unnecessarily.

## Security commitments
- Feed signatures must be verified before import.
- Client browsing history is local by default.
- Unknown URLs are not represented as safe.
- Platform-level filtering must be opt-in and documented.
- Releases should include dependency and build provenance information as maturity permits.
